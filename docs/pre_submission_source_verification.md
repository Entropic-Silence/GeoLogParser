# Pre-submission source verification ledger

This document is the human-check companion to
[`datasets/source_verification_ledger.yaml`](../datasets/source_verification_ledger.yaml).
It records the provenance of every external source that has entered an
internal extraction, Silver-reference, robustness, or downstream protocol
experiment. The project may process a source before its rights are fully
verified; that permission is for internal/provisional work only and is not a
publication or redistribution licence.

## How to use this ledger

1. Run `python3 scripts/build_source_verification_ledger.py` after an
   acquisition or manifest change. The YAML records a deterministic inventory
   hash and hashes of the local acquisition/content manifests.
2. Before submitting a manuscript or releasing data, inspect every record with
   `requires_human_check_before_submission: true`.
3. Verify the exact repository item/version, licence/terms, file-level scope,
   attribution, privacy and sensitive-location status, embedded third-party
   content, and whether derived page assets may be redistributed.
4. Record the human decision in the ledger (or in a dated successor ledger);
   do not edit historical experiment manifests in place. A source remains
   `UNVERIFIED_SOURCE`, `RIGHTS_CONFLICT`, or `QUARANTINE_INTERNAL_ONLY` until
   that check is complete.

The YAML is the authoritative machine-readable record. `datasets/data_registry.yaml`
remains the discovery/acquisition registry; it is not a licence grant. Local
paths point to `/data/GeoLogParser`, where large source files are kept outside
the Git repository.

## Status vocabulary

| Status | Meaning | Submission use |
| --- | --- | --- |
| `CLAIM_CAPTURED` | Repository or publisher licence claim and local acquisition evidence are recorded; item/content/privacy review may still be incomplete. | Human check required before use in a released benchmark or manuscript claim. |
| `UNVERIFIED_SOURCE` | Access, file scope, licence, or terms evidence is incomplete. | Internal/provisional experiments only. |
| `RIGHTS_CONFLICT` | Repository metadata contains contradictory access/licence signals (for example an embargo plus CC BY claim). | Quarantine; do not redistribute or present as cleared. |
| `SYNTHETIC_KNOWN_GT` | Labels are generated by the GeoLogParser renderer and are reproducible, not human/expert labels. | Controlled experiments; generated assets still need a release-licence decision. |

## Experiments and labels

The ledger covers the Padova, BGS, Mendeley, Chinese quarantine, and
structured-source inputs used by Paper I--III protocol runs, as well as the
synthetic corpus. Machine-derived records are described as **Silver**,
**pseudo-label**, or **machine-adjudicated**. They must not be called human,
expert, or Gold Ground Truth without an independently documented annotation
source. Accuracy against a Silver reference is agreement-to-Silver, not human
accuracy.

Model weights, prompts, code, and literature have their own manifests and are
not data-source rights evidence; their licences must be checked separately in
the release checklist.

## Human sign-off fields

For each YAML record, the final reviewer should append or record in a successor
ledger:

```yaml
human_verification:
  reviewer: TBD
  reviewed_utc: TBD
  exact_item_version_confirmed: false
  licence_text_captured: false
  file_scope_confirmed: false
  attribution_confirmed: false
  privacy_review: TBD
  sensitive_location_review: TBD
  embedded_third_party_content_review: TBD
  derived_asset_redistribution: TBD
  decision: TBD  # ELIGIBLE | ELIGIBLE_INTERNAL_ONLY | EXCLUDE | AMBIGUOUS
  notes: TBD
```

No `true` or final decision is implied by the automated ledger. The current
ledger is intentionally a pre-submission queue, not a claim that all sources
are cleared.
